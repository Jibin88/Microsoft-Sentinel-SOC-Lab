# Microsoft Sentinel SOC Lab

## Project Overview

This project is a practical Security Operations Center (SOC) lab developed to demonstrate Windows security monitoring and failed login detection using Microsoft Sentinel.

The lab uses a controlled virtual environment with Kali Linux as the testing machine and Windows 10 as the victim/monitoring machine.

The main focus of the project is detecting repeated failed login attempts using **Windows Security Event ID 4625** and **Kusto Query Language (KQL)**.

---

## Project Objectives

- Build an isolated SOC monitoring environment using VirtualBox.
- Configure a Windows virtual machine for security monitoring.
- Simulate controlled failed SMB login attempts from Kali Linux.
- Generate and investigate Windows Event ID 4625.
- Connect the Windows machine to Azure using Azure Arc.
- Install and configure Azure Monitor Agent (AMA).
- Configure a Data Collection Rule (DCR).
- Send Windows Security events to Microsoft Sentinel.
- Create KQL queries for security event analysis.
- Configure a Microsoft Sentinel Analytics Rule.
- Understand the basic SOC detection and investigation workflow.

# 1. Windows Security Event ID 4625

Windows Security Event ID **4625** is generated when an account fails to log on.

The event can provide useful information for SOC investigation, including:

- Target username
- Source IP address
- Logon type
- Workstation name
- Authentication package
- Failure status
- Failure reason

In this project, Event ID 4625 was used as the primary detection event.

---

# 2. Kali Linux Failed Login Simulation

A controlled SMB authentication test was performed from Kali Linux against the Windows virtual machine.

Example command:

```bash
smbclient -L //192.168.56.102 -U 'socuser%WrongPass123!'
```

The incorrect password generated:

```text
NT_STATUS_LOGON_FAILURE
```

Multiple controlled attempts were performed to generate Event ID 4625 on the Windows machine.

This activity was conducted only inside the isolated virtual lab.

```text

```

```text

```

The Windows Event Log data source included Event ID 4625.

Example XPath filter:

```text

```

This configuration allowed failed logon events to be collected for Sentinel monitoring.

# 8. KQL Monitoring Query

Kusto Query Language (KQL) was used to search and analyze the collected security events.

Example query:

```kusto
SecurityEvent
| where EventID == 4625
| where Computer == "DESKTOP-9LVMV9D"
| project TimeGenerated, TargetUserName, IpAddress, LogonType, WorkstationName
| order by TimeGenerated desc
| take 10
```

This query displays recent failed login events and important investigation fields.

---

# 9. Failed Login Detection Query

A detection query was created to identify repeated failed login attempts from the same source.

```kusto
SecurityEvent
| where EventID == 4625
| summarize FailedAttempts = count()
    by Computer, IpAddress, bin(TimeGenerated, 5m)
| where FailedAttempts >= 3
| order by TimeGenerated desc
```

### Detection Logic

The query:

1. Searches for Event ID 4625.
2. Groups events by computer and source IP.
3. Creates a 5-minute time window.
4. Counts failed login attempts.
5. Identifies groups with 3 or more failed attempts.
6. Sorts the results by time.

This provides a simple brute-force style detection mechanism for the lab.

# 16. Limitations

This project was developed as a small educational SOC lab.

Limitations include:

- The environment uses virtual machines rather than production systems.
- The detection scenario focuses mainly on failed login events.
- The lab does not represent a complete enterprise SOC environment.
- Alert generation depends on event timing and Sentinel rule execution windows.
- The environment was designed for controlled educational testing.
